# Reliability findings register

Internal tracking for the public
[reliability contract](../src/content/docs/reference/reliability.md). This
file is not published. The contract never cites these IDs; it links here for
open defects.

Rows were seeded from the 2026-09-29 reliability survey and re-checked against
`main` at `b8366af`. Evidence names durable symbols (`module::Type::method`),
never line numbers. Test paths follow the contract's convention: library tests
by module path, integration tests by file under `crates/casita/tests`.

## Working agreement

- **A fix lands with a fail-before/pass-after test.** Name it in the row's
  falsifier column. A test that would pass without the fix proves nothing.
- **Contract, tests, and code change in one PR.** When they disagree, stop and
  record a row here before changing any of them.
- **Every PR names what it touches**: "Contract clauses touched: C…; register
  rows: F…" (see `.github/pull_request_template.md`).
- **Re-audit once per milestone.** Grade every clause against its full scope
  in the contract:
  - `HOLDS`: every in-scope path has a passing falsifier and no row shows a
    violation;
  - `VIOLATED`: a row here shows the clause broken somewhere in scope;
  - `CAN'T-TELL`: no violation is known, but some in-scope path has no
    falsifier. The missing harness goes into the [harness backlog](#harness-backlog).

  A clause takes the grade of its weakest in-scope path.

Statuses:

| Status | Meaning |
|---|---|
| `lead` | Hypothesis. The first step is a falsifier test |
| `verified` | Confirmed on `main` by source reading or a test; not fixed |
| `fixed` | Fixed on `main`, with a fail-before/pass-after test |
| `in review (#N)` | A fix or re-grading test is in open PR #N, not yet on `main` |
| `accepted-weakening` | The owner accepted a weaker guarantee; the contract states it |
| `won't fix` | The owner declined |

## Commit-validator waivers

Commit points (roadmap Appendix A) check their transition before the durable
step with `crate::invariant::check`: debug builds panic, and release builds
compiled with `--cfg casita_invariants` refuse the commit as corruption.
Costly checks (re-hashing, replay) run only in debug builds. These are the
invariants that were considered and not implemented, and why.

| Commit point | Invariant | Reason |
|---|---|---|
| wal3 metadata commit | collection removes no root target | Resolving root targets takes per-root shard reads. `apply_mutation` already refuses a retained set missing a root target (`InvalidRetainedSet`), and the validator checks that exactly the retained set survives. Memory and Turso check root presence directly |
| wal3 GC fence | barrier still owned when the fence publishes | The GC barrier is force-acquired, so losing it mid-fence is a legal race. The fence republishes identical logical state (checked by `wal3.gc_fence`), and `collect_wal_scoped` re-checks ownership before deleting |
| Turso, wal3, memory commits | root targets closure-validated | Existing checks kept: `validate_root_closures_tx`, `validate_root_closures`, `validate_root_closures_sharded`. Re-walking costs O(closure) |
| Turso initial `repository_state` insert, schema init, WAL checkpoints, facts edits, records in the commit transaction | transition invariants | No previous logical state (init, schema), no row change (WAL checkpoint), or opaque caller data covered by the enclosing transaction (`check_metadata_tx`). Facts clears are validated (`turso.facts_clear`) |
| Pack pointer | version or ETag monotonic | Versions and ETags have no order (see the contract's S3 axiom). The conditional write uses the same witness; monotonicity is checked on `generation` |
| Pack pointer | every shard inside a shard map exists | Needs reads. Objects the pointer names directly are checked in debug builds against an in-memory witness of this handle's writes |
| `LocalCatalogLock::compare_and_put` | pointer invariants inside the lock | A byte-level CAS primitive also used with non-catalog payloads by tests; its only production caller validates first |
| State-catalog pointer candidate | no retired pack referenced | State mode deliberately reintroduces identical retired pack bytes, and `reclaim_payloads` re-checks membership before deleting; only the delta's own removals count |
| `PreparedCatalog::{commit,abort}` | `Committed` iff the head contains the candidate | Needs a metadata read. The payload-catalog check in every metadata commit covers the success path; F-01 was re-graded harmless |
| Tombstone deltas, replacement records, sidecars | `name == blake3(bytes)` | The name is computed from the same bytes immediately before the write |
| Loose chunks, manifests, outboards, pages | `name == blake3(bytes)` | Chunks are verified by `put_chunk` (decompress and hash); the others are named by logical id, not by content |
| Unmarked retirement (`retire_collected_path` standalone) | deleted ∉ pinned | No pin ledger exists on that path |
| `claim_deletions_validated` in `repository::collection`, `wal3_shard::delete_paths_pinned` | deleted ⊆ claimed; claimed ∩ pinned = ∅ | Not yet wired; `blob::pinned_store::validate_deletion_claim` and `validate_deletion_finish` apply unchanged |
| wal3 shard put, release builds without `casita_invariants` | an existing shard hashes to its name | Costs a GET per name-taken put |
| wal3 shard put, fresh write | `name == blake3(bytes)` | The encoder computes the name from the bytes it returns |
| wal3 shard put on local storage | an existing shard hashes to its name | `chroma_storage` local puts ignore conditions and never report the name taken |
| wal3 barrier initialization, `put_barrier` | transition invariants | Initialization writes a constant with `IfNotExist`; `put_barrier` is checked at its callers, which hold the previous state and lease |
| wal3 hold release | the token was present | Needs a scan of all holds, and removing an absent token legitimately fences an ambiguous admission |
| wal3 hold catalog after commit | one exclusive hold, unique tokens | Built inside the wal3 commit; `Coordination::holds_at` rejects overlap on read and root names are unique map keys |
| Pin ledger | `logical_prune ⇒ collector` | Wrong at the ledger layer: `begin_prune` and `begin_prune_recovering` admit a prune with no collector in every implementation, and production collection always holds one. A comment at the check site records this |
| Pin ledger | at most one collector | Enforced by the type (`Option<PinToken>`); the collector token's uniqueness is checked |
| Local pin ledger | `revision == prev + 1` | Reader bookkeeping advances the durable revision past readers, and one frame carries a group; the local ledger checks `> prev` |
| Local journal append | full inventory check | Only the records a frame touches are checked, keeping appends O(change); untouched records were checked when written |
| Local journal checkpoint, `casita_invariants` release builds | checkpoint == replay(previous + frames) | Replay costs about as much as the checkpoint; debug builds only. The new-epoch check always runs |
